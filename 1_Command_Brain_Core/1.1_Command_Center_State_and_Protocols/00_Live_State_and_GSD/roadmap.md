## Phase 3: Automation

- Evaluate Context Mode for session hygiene.
- Evaluate ClaudeMem against gbrain/VCOS memory.
- Set up nightly semantic indexing after the active memory layout stabilizes.
- Add Codex adversarial review as a standard quality gate for high-risk work.

## Phase 4: Agentic OS Surface

- Create a domain-task-skill-automation map.
- Create an automation registry with approval gates and output destinations.
- Add observability requirements for active outcomes, blockers, approvals, skill candidates, and automation health.
- Turn safe routines into dashboard buttons only after the registries define ownership and gates.

## Phase 5: AIOS Maturity

- Initialize VCOS HQ as a private GitHub-backed repo for issues, diffs, PRs, and routine source.
- Open VCOS HQ as an Obsidian vault with `Home.md` as the navigation layer.
- Activate AIS-OS as a pointer-first operating pattern: onboarding summary, weekly Four C audit, weekly Three Ms level-up, and one shipped artifact per run.
- Activate Graphify as the lightweight project graph layer: query `graphify-out/graph.json` before broad file reads and import generated wiki/Obsidian outputs only through quarantined graph-import folders.
- Decompose the old Chief of Staff mega-prompt into durable HQ protocols, Mini Intern roles, Graphify/GBrain retrieval, and cadence routines.
- Run a weekly Four C audit: context, connections, capabilities, cadence.
- Verify read-first ClickUp, Drive, GitHub, and approval-surface integrations before adding write actions.
- Promote repeated SOPs into skills only after the level-up interview confirms repeated value.

## Phase 5.5: Daily Operating System

- Create the Daily Command Brief routine as the default start-of-day operating loop.
- Test Graphify + GBrain daily resume on AgentOSync before applying to all projects.
- Keep Hermes in read-only night-brief mode until two clean reviewed runs prove reliability.
- Promote Hermes from read-only to draft-only only after approval gates, source scopes, and failure modes are documented.

## Phase 6: Employee Template Productization

- Refactor `4_Reusable_Systems_and_Skills/4.1_VCOS_Employee_OS_Template` into the generic deployable employee OS template.
- Separate HQ governance, reusable template, vertical packages, and client instances.
- Add a template manifest, fast-path agent instructions, role interfaces, approval gates, and Four C audit.
- Use dealerships as the first vertical employee package only after the mock missed-call workflow passes internally.
