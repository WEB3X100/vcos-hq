# AI Native Company Arsenal Activation

Purpose: turn the cloned Arsenal repos into a usable VCOS operating pattern for building an AI-native service company and software factory.

Core rule: the Arsenal is not the brain by itself. VCOS HQ remains the command brain; Obsidian is the human navigation layer; Graphify maps relationships; QMD routes agents to relevant local files/snippets; GBrain recalls curated memory; project workspaces and tools execute.

## Operating Thesis

VCOS is building a company where AI is the operating system, not a productivity add-on.

Every important workflow should become a closed loop:

1. Sensor: capture the work, request, meeting, browser state, repo state, or metric.
2. Policy: decide what should happen, what is allowed, and where approval is required.
3. Tool: execute through the smallest safe interface.
4. Quality gate: review, test, score, or adversarially inspect.
5. Output: create the deliverable, brief, PR, demo, document, or decision packet.
6. Metric: track cycle time, cost, quality, conversion, and variance.
7. Learning update: save the decision, blocker, reusable win, or bug-prevention rule.

If a workflow does not capture artifacts and improve the next run, it is not yet AI-native.

## Revenue-First Constraint

Do not use this Arsenal map as an operating manual for tools that are not running. It is a capability map, not proof of execution.

Right now, the only loops that compound toward near-term revenue are:

1. AgentOSync Revenue Proof Loop: barbershop callable demo, outbound/content, booked demos, paid pilot.
2. Amax Internal Proof Loop: daily revenue-ops control brief from real CRM/booking/invoice/team data.
3. Employee Repo + Skill Loop: package workflows proven 3+ times into reusable employee repos and skills.

Claude Code is the primary builder for these loops. Any Arsenal tool that does not remove a current blocker from one of these loops stays parked.

## Two Layers, One System

### Second Brain remembers

- Obsidian: human-friendly navigation through VCOS HQ.
- Graphify: relationship map before broad file reads.
- QMD: local context router over approved markdown, docs, transcripts, and knowledge-base collections.
- GBrain: curated semantic/text recall for briefs, reviews, office hours, and resumes.
- Meetily: meeting capture and decision extraction, after approval for sensitive calls.
- Design Extract outputs: design system snapshots and brand references.
- CodeBurn reports: token/cost/cycle-time telemetry.

### AI OS acts

- GStack / GSD: specs, office hours, reviews, QA, and ship discipline.
- Browser Harness: repeatable browser operations and web workflow memory.
- Impeccable: frontend/brand quality gate.
- Caveman: concise agent handoffs and low-noise multi-agent output.
- ToolJet / VCOS Mission Control: operator dashboards and control surfaces.
- AIS-OS routines: weekly Four C audit and one shipped artifact at a time.
- Future Hermes: read-only night brief first, then draft-only, then approved action phases.

## Closed-Loop Company Modules

### 1. Command and Strategy Loop

Inputs: `state.md`, `active-context.md`, ClickUp, Daily Command Brief, decisions, blockers.

Tools: AIS-OS, GBrain, Graphify, QMD, CodeBurn.

Output: morning cockpit with active outcomes, blockers, human decisions, agent-executable next actions, and approval requests.

Metric: fewer cold-start tokens, faster resume time, fewer repeated decisions.

### 2. Software Factory Loop

Inputs: product brief, repo state, requirements, tests, user-facing proof target.

Tools: GStack/GSD, Codex, Claude Code, Browser Harness, Impeccable, CodeBurn, Caveman.

Output: working demos, PRs, verified UI, handoff notes, and cost/quality telemetry.

Metric: cycle time from spec to verified demo, defect rate, token cost per shipped artifact.

### 3. Design and Brand Loop

Inputs: brand examples, competitor sites, existing client materials, screenshots.

Tools: Design Extract, Impeccable, Figma/Obsidian notes, Graphify.

Output: design language capsule, tokens, UI review rubric, demo-ready brand surface.

Metric: fewer redesign loops, stronger first impression, consistent client-ready visuals.

### 4. Revenue and Service Ops Loop

Inputs: target niche, lead list, proof wedge, outbound/channel signals, pilot criteria.

Tools: Career Ops pattern, Browser Harness, AgentOSync, ClickUp, GBrain.

Output: qualified opportunity pipeline, demo queue, pilot packets, approval-gated outreach drafts.

Metric: booked demos, pilot conversion, revenue per operator hour, handoff completeness.

### 5. Meeting and Knowledge Loop

Inputs: calls, transcripts, notes, decisions, open questions.

Tools: Meetily, GBrain, Obsidian, Graphify.

Output: decisions, action items, reusable objections, client context capsule.

Metric: less meeting recall loss, faster follow-up, cleaner handoffs.

### 6. Operator Console Loop

Inputs: active projects, blockers, token metrics, approvals, project statuses.

Tools: ToolJet or VCOS Mission Control, CodeBurn, ClickUp, Graphify summaries.

Output: live command surface for Umair and future Hermes.

Metric: one screen answers "what matters, what is blocked, what can agents do next?"

## Activation Rules

- Do not import `6_Arsenal/repos/` into GBrain or Graphify wholesale.
- Create curated capsules and graph summaries first.
- Use repo READMEs for evaluation; read source only when adopting that repo for a specific workflow.
- Install repo-specific skills or CLIs only when a real project requires them.
- Claude Code should implement the first operating routines before new platform/tool expansion: `content-intel-routine`, `sprint-closer`, and `skeptic-review`. Defer `morning-cockpit` until one focused lane needs a daily brief.
- QMD may index approved markdown/docs/transcripts collections, but it should not become a parallel vault or default whole-HQ crawler.
- Browser Harness may not connect to authenticated or client-sensitive sessions without human approval.
- Design Extract may not be used on authenticated/client-sensitive pages without human approval.
- CodeBurn may read local AI logs, but shared/exported reports should remove secrets and client-sensitive details.
- Caveman is a communication discipline first; global install is optional and gated.
- Impeccable is a frontend QA gate, not a reason to redesign stable working software.
- Career Ops is a pattern to generalize, not a job-search priority unless explicitly requested.

## Morning Cockpit Query

When starting VCOS HQ, use this sequence:

1. Read fast-path HQ files.
2. Query GBrain for the active outcome or domain.
3. Query Graphify for registered graphs before reading many files.
4. Query QMD when the next step is finding the right local note, transcript, or source snippet.
5. Pull ClickUp only if the task touches active execution.
6. Produce a brief with outcomes, blockers, approvals, next actions, and the smallest next context file.
