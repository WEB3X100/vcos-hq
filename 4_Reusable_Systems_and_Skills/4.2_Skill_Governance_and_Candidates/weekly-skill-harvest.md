# Weekly Skill Harvest

Purpose: turn weekly learning into reusable Mini Intern capabilities without bloating every intern.

## Cadence

Run once per week, ideally Friday or Sunday, after real work has produced enough signal.

## Questions

1. What did we do 3+ times this week?
2. What did we explain to Claude/Codex more than once?
3. What tool workflow did we learn that should not be re-researched?
4. What output got meaningfully better after a prompt, rubric, or process change?
5. Which department should own the repeatable part?
6. What is the smallest input packet and output packet?
7. What approval gate protects the business?
8. Is this an experiment, pattern, skill candidate, validated skill, installed capability, or marketplace skill?

## Harvest Buckets

| Bucket | Use When | Action |
| --- | --- | --- |
| Keep as note | Useful once, unclear repeat value | Save only to the relevant project or decision note |
| Add to registry | Repeated shape, but not ready to install | Add row to `skill-registry.md` |
| Promote to candidate | Trigger + input/output + approval gate are clear | Create or update candidate folder |
| Install into department | Validated enough for a Mini Intern to use | Update department pack `capabilities.md` |
| Package for marketplace | Client-safe, reusable, and tested | Move summary into `4.4_Validated_Marketplace_Skills/` |
