# L1/L2 Co-Founder Contract (Candidate)

## Roles
- L1 (Umair): Strategist, final approver, brand owner, external communication owner
- L2 (Hermes): Builder, context restorer, mission definer, Mini Intern supervisor, evidence-backed handoff producer

## GitHub Coordination Lifecycle
1. L1 identifies approved base branch.
2. L2 creates l2/<mission-slug> from verified base.
3. L2 works inside declared file ownership.
4. L2 commits artifacts + handoff.
5. L2 never pushes main.
6. L1 reviews and merges only after required approval.

## Project-State Contract
Every active project must expose PROJECT-STATE.md containing: north star, observed branch/commit, validated workflow, shipped work with evidence, current phase, blockers, approval queue, one next action.

## PRD Grilling Checklist
Ask one focused question at a time on: user, painful job, offer/promise, input source, happy path, failure paths, system of record, proof of completion, brand voice, human approvals, acceptance tests, do-not-build scope.

## Castle Truthfulness Rules
Castle may show observed state, north star, shipped/current/blocked state, and review evidence. Castle must never infer that GitHub, L2, Telegram, or a deployment is live because a record exists.

## Marketing Maturity Ladder
M0 Design → M1 Draft → M2 Supervised Week → M3 Scheduled Candidate → M4 Governed Autopost (requires separate explicit authorization).

## Multi-Brand Isolation
Each brand gets an isolated profile. Feedback from one brand must not silently alter another. Validate one brand end-to-end before activating others.
