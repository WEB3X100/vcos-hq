# One-Person AI Agency Sales OS

Use this skill to turn sales/advice transcripts into a practical VCOS revenue loop for AgentOSync, Dealership OS, Amax/travel, and future SMB Mini Intern kits.

This is not a hype-capture skill. It converts outside advice into a constrained operating system with inputs, outputs, proof lanes, and approval gates.

## Core Pattern

The reusable system is:

```text
Offer wedge -> proof asset -> lead source -> qualification -> discovery call -> commitment -> delivery packet -> proof/content -> retention call -> upsell/referral
```

For VCOS, the first proof lane is Dealership OS, then Amax/travel, then other SMB verticals once a repeatable offer exists.

## When To Use

Use when the user says or implies:

- "incorporate this for sales reusable systems"
- "turn this transcript/course into a system"
- "AI agency sales OS"
- "one-person AI business"
- "cold email / Upwork / LinkedIn / Loom / discovery call"
- "how do we package this for AgentOSync"
- "build a repeatable sales workflow"

## Non-Negotiables

- Draft-only by default.
- Human approval is required before outbound messages, public posts, calendar links, proposal terms, pricing, payment links, CRM/customer-data mutation, client-facing claims, or external sends.
- Do not copy another creator's claims, guarantees, numbers, scripts, or funnel language verbatim into VCOS collateral.
- Do not start with full automation. Start with manual packets, prove the loop 3 times, then promote.
- Do not treat "free work" as the default VCOS offer. Use it only as a deliberate proof wedge when it protects reputation and creates reusable evidence.
- Payment-link or card-on-file tactics require explicit human approval and legal/operational review before use with real clients.

## Inputs

Minimum input packet:

- Source material or transcript.
- Target vertical: dealership, travel, barbershop, local SMB, or internal Amax.
- Offer wedge: website, missed-call recovery, lead follow-up, review generation, finance cleanup, support automation, or custom AI system.
- Existing proof assets, if any.
- Approval surface: current thread, ClickUp, Slack, Telegram, or meeting.

Optional input packet:

- Prospect list or Upwork/job links.
- Call transcript or notes.
- Current demo URL, deck, Loom, or proof artifact.
- Known objections, pricing constraints, or client risk.

## Outputs

Produce only the packets needed for the current task:

### 1. Offer Wedge Packet

- Target buyer.
- Pain being positioned.
- Outcome promise in plain language.
- Smallest demo/proof asset.
- Risk reversal, if any, marked as draft-only.
- What approval is needed before use.

### 2. Lead Source Packet

- Channel: warm network, Upwork, LinkedIn, cold email, local list, ClickUp lead, referral, content inbound.
- Fit criteria.
- Disqualifiers.
- First message angle.
- Required proof link or attachment.

### 3. Discovery Call Packet

- Opening diagnosis questions.
- Pain-positioning questions.
- Current process map.
- Cost of inaction.
- Stakeholder and approval map.
- Next call to book before leaving the call.
- Follow-up artifact to prepare.

### 4. Delivery Handoff Packet

- Client goal.
- Exact workflow to build.
- Data/tools needed.
- Acceptance criteria.
- Human approval gates.
- Risk/failure mode.
- Demo deadline.

### 5. Proof And Distribution Packet

- Sanitized before/after claim.
- Screenshot/Loom/deck proof object.
- LinkedIn/YouTube/script draft, if requested.
- Confidentiality exclusions.
- Approval needed before publishing.

### 6. Retention, Upsell, And Referral Packet

- Biweekly review agenda.
- Performance metrics.
- Churn risk signals.
- Natural next offer.
- Specific referral ask by industry/persona.
- Commission or incentive idea, marked draft-only.

## Workflow

1. Extract the useful operating principles from the source material.
2. Map each principle to VCOS terms: Sales Ops, Delivery, Marketing, Reviewer QA, Approval/Decisions.
3. Choose the smallest active proof lane, usually Dealership OS unless the user names another.
4. Produce a draft-only packet, not an automated campaign.
5. Identify the first manual validation run.
6. If the pattern is used successfully, update the Skill Registry and Sales department pack.

## First VCOS Adaptation

For Dealership OS, the best starting wedge is:

```text
One-day sales recovery packet:
missed leads + stale listings + owner morning brief + next best follow-up actions
```

The first manual validation should produce:

- One owner-facing morning brief.
- One 4-minute walkthrough script.
- One approval-gated follow-up message set.
- One delivery handoff packet for any workflow the owner approves.

## Validation Criteria

After each use, record:

- Did it create a clearer offer?
- Did it reduce time to prepare outreach or a sales call?
- Did it prevent an approval-gate mistake?
- Did it produce a reusable proof artifact?
- Did it lead to a meeting, client decision, upsell, referral, or better positioning?

Promote only after 3 successful uses or clear cross-client leverage.
