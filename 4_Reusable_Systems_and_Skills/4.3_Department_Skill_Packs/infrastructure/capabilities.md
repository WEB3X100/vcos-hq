# Infrastructure Mini Intern Capabilities

Purpose: maintain deployable skeletons, runtime choices, repo hygiene, env templates, and safe setup paths.

## Candidate Capabilities

| Capability | Status | Job |
| --- | --- | --- |
| Employee repo skeleton maintenance | Active | Keep VCOS Employee template deployable and GitHub-backed |
| Runtime selection rubric | Candidate | Choose local Claude Code, n8n, Trigger.dev, Modal, Managed Agents, OpenClaw/Hermes, or custom service |
| GitHub sync and env template | Pattern | Keep repos backed up without leaking secrets |
| Skill installation packaging | Pattern | Install validated department capabilities into Mini Intern repos |
| Superpowers development discipline | Evaluation candidate | Use clarify-design-plan-code-verify-review workflow for medium/complex builds and production-sensitive automations |
| Session context discipline | Active protocol | Rewind wrong turns, clear between missions, create handoffs, use sidecars for noisy work, and keep durable state in files |

## Approval Gates

Human approval is required before pushing remote changes, credential setup, production deploys, destructive repo actions, or runtime cost commitments.

## Superpowers Fit

Use for:

- Employee template refactors
- client workflow code
- n8n/Trigger.dev/Modal implementations
- frontend demos with multiple design choices
- debugging repeated failures
- anything requiring tests, review, or deployment gates

Skip for:

- quick markdown updates
- simple registry edits
- low-risk planning notes

Do not let Superpowers override VCOS human approval gates.

## Session Economy Fit

Use for every long or high-value mission:

- check context/cost when available
- keep the session under control instead of filling the window
- create handoffs before clearing
- save durable decisions to files
- use sub-agents/sidecars for noisy scanning when allowed
- convert large docs into Markdown/summaries before loading
